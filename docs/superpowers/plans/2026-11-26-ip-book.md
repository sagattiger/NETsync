# IP Book Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** A built-in NETsync plugin "IP Book": networks and the IPs in them with who uses each, learned from discovery
and edited by admins, pinged with optional alerts, with encrypted admin-only secrets and a spreadsheet import.

**Architecture:** Pure logic modules (networks/warnings, values/secrets, learning, import) under
`netsync/plugins/builtin/ipbook/`, unit-tested without a database, plus thin DB/API/service layers like the CrowdSec
plugin. IP health uses one virtual device and the normal metrics/services pipeline so Problems and notifications
work unchanged. React page at `/ipbook` (network list left, header + table right).

**Tech Stack:** FastAPI, SQLAlchemy async (TimescaleDB), icmplib, Fernet (`netsync.probing.secrets`), openpyxl
(new backend dependency), React + Tailwind + TanStack Query.

**Spec:** `docs/superpowers/specs/2026-11-26-ip-book-design.md`

## Global Constraints

- Plugin name `ipbook`, label "IP Book", router at `/api/plugins/ipbook`, page `/ipbook` and `/ipbook/:networkId`.
- Only admins create/edit/delete networks, rows, columns, run imports, reveal secrets. Operators and viewers: read-only, no secrets, no sensitive rows; any role may Ping.
- Secrets never leave the API except through the reveal endpoint (admin, audited). Never in list/search responses, logs, errors, problem output, notifications, AI tools, MCP or the public API.
- Problems for **sensitive** rows use the neutral name `IP Book: sensitive entry #<row id>` and output `down` / `up` (no IP, no service name).
- Values a person set (`manual_keys`) are never written by discovery; nothing is deleted automatically.
- Ping every 5 minutes (setting `interval_min`, 1–60); an IP is down after **3** missed pings in a row; up on the first answer.
- Learned networks: IPv4 only, skip loopback, link-local, multicast, /32 and prefixes wider than /16.
- Warnings: overlap; duplicate IP (Shared IPs rules); private IP in no network; learned row missing (device not discovered for **7 days**); network over **90 %** used; unresolved import conflict.
- Public repo: tests and docs use only invented data (192.0.2.0/24, 198.51.100.0/24, 10.0.0.0/24, names like `app01.example.test`).
- Built-in column keys, labels and types exactly as the spec's Columns table.

## Review Focus

- A non-admin request for a sensitive row by id (`GET /rows/{id}`, search hit, a network view, the Ping endpoint's response) must return 404 / omit it, not leak its fields. Test in Task 6.
- Editing a row and sending a secret field back empty must keep the stored secret (the UI never has the value). Test in Task 3.
- A sheet with a title banner, merged header cells or trailing empty columns/rows must still find the header and skip blanks. Test in Task 5.
- Overlapping networks must both list a row whose IP falls in both, and the overlap warning must name both. Test in Task 2.
- Turning "Alert when down" off (row or network) must remove the IP's service, so a stale problem doesn't stay open. Test in Task 7.
